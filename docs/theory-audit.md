# Harness-X 理论审计与修正版

## 结论

附件中的工程方向大体正确，但五个“定理”都不能按现有条件作为严格定理。
最重要的修正是：软件智能体的一次任务不是标准的重复 bandit；固定 LLM 在任务间
也不会因 ε-greedy 自动更新参数。因此，Xiaopu 不采用无条件随机探索，而采用
**证据触发、预算受限的候选分支 + 确定性验证**。

## D1：纯 ReAct 必为 Θ(T) —— 条件不足

原证明先假定每集期望 gap 为常数 `c>0`，再求和得到线性 regret；结论实际已被
假设写入。`q^h` 还隐含每步独立、同分布和“任一步错即整集失败”，现实中工具反馈
会改变后续条件概率，错误也可恢复。

可成立的版本：若重复任务分布平稳、策略与外部记忆均不更新，并且每轮存在统一
下界 `E[Δ_t] >= c > 0`，则 `R(T) >= cT = Ω(T)`；若 gap 有上界，则为 Θ(T)。
这说明需要学习或纠错闭环，但不能单独推出必须使用 ε-greedy。

## D2：子目标 ε-greedy 得到 O(sqrt(T)) —— 缺失学习模型

原式中的指数残差直接假设“探索次数使错误率指数下降”，但没有定义被更新的后验、
可辨识性、反馈噪声或候选臂数量。固定 LLM 加随机高温采样不会自然产生该收敛率。

修正版选择规则：对候选方案 `g` 使用

`score(g)=predicted_success(g)-λ*cost(g)-μ*risk(g)+ν*information_gain(g)`。

仅在以下任一条件成立时分支：验证失败；两个候选得分接近；错误类别未知；或任务
影响面高。分支预算由最大工具调用、时间和费用共同限制。此规则没有虚构 regret
保证，但能在一次性 SWE/terminal 任务上直接优化成功率/成本。

## D3：αW >= δL 不是“无损压缩条件”

token 容量不能等同于 Shannon 信息量；自然语言摘要一般是有损的。真正需要保存的
不是全部 transcript，而是任务的充分状态：目标、约束、计划、已改文件、测试证据、
失败指纹、关键原文位置。Xiaopu 采用“结构化状态常驻 + 最近交互 + 按需重读”，并
明确承认无法保证检索召回率趋近 1。

## D4：验证器召回率相乘需要条件独立

`1-r_eff=Π(1-r_i)` 只在各级漏报条件独立时成立；lint、类型检查和测试的失败高度
相关。级联成本还应按“通过/失败后的路由概率”计算，而非一律使用错误召回率。
正确工程结论仍成立：先执行廉价、确定性的检查，再执行相关测试，最后才使用昂贵
的 LLM/视觉 judge；但召回率必须用实际标注集测量。

## D5：MCTS 条件只是启发式

`q^h`、验证器相关系数 `ρ` 和节点爆炸式之间没有给出转移/奖励模型，因此不是临界
定理。代码任务的动作空间巨大且不可逆副作用多，完整 MCTS 通常不划算。Xiaopu 的
替代方案是失败后生成少量互斥修复候选，在隔离副本或可回滚检查点验证，再提升胜者。

## 实际最优目标

不存在脱离模型、预算、数据集和运行环境的“世界最优 harness”。可操作的目标是：

`maximize P(task_pass) subject to cost<=B_c, time<=B_t, risk<=B_r`。

实现优先级为：环境理解 → 精确工具 → 权限/隔离 → 持久任务状态 → 错误分类与恢复
→ 分层验证 → 上下文治理 → 仅在不确定时搜索。这个顺序比无条件增加规划轮次或
随机探索更可能同时提升 Terminal-Bench、SWE-bench 与 PPT 任务效果。
